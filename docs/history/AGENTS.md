## Updating prices through the Scalable MCP (read-only!)

Use only `get_security_chart`, `get_security_quote`, `search_securities`. Never call order, savings-plan, watchlist, price-alert or other write tools. Omit `portfolioId`.

Timeframes (tested 25.09.2026): `year_to_date` = one point per trading day = daily close (~20–22 UTC), from 1 January of the current year, ~7k tokens per call; `seven_days` = 30-min points, the last point per day (~20:59 UTC) is the close; `one_day` = minutes, today; `one_month` = 2-hour points, the last one (~19:30 UTC) is NOT the close; `one_year` = every 2nd trading day, `max` = monthly – never use those for daily rows. No date parameter. Ignore `closingReferencePoint`. Since `year_to_date` restarts every January, never delete old rows.

**Subagents (user rules, 27.09.):** Haiku agents **only for price lookups**, always with clear, script-checked instructions and thinking ON. Haiku has no effort setting: start them as agent type `price-fetcher` (model haiku) and begin every fetch prompt with the line `Thinking ON: think step by step before each tool call and before writing each file.` One agent per batch of ≤ 10 ISINs for updates, ≤ 3 for backfills (Haiku context 200k). **Everything else** delegated (UI, code, review) runs on **Opus 5.5 with effort high or xhigh**: the Agent tool has no effort parameter, so use agent type `dashboard-designer` (Opus, xhigh) or `opus-engineer` (Opus, high), both in `C:\Users\simon\Downloads\.claude\agents\`. Ask the user whenever something is even slightly unclear.

**Every update follows `UPDATE_PRICES.md`** (user, 25.09.: fetch the intraday prices on every update):
`python data/update_prices.py --plan` (empties `data/incoming/`, prints one ready agent prompt per batch) → one `price-fetcher` agent per prompt, all at once: per ISIN `get_security_chart(isin, "seven_days")`, the points since the last final date copied verbatim to a new file `data/incoming/<ISIN>.csv` → `python data/update_prices.py --finish` (check → merge → rebuild → tests → status block in `HANDOFF.md` → report; prints a ready re-fetch prompt for missing/bad ISINs). `--check`, `--dry-run` and the plain run remain available as single steps. One seven_days call gives both: the last point per Berlin date = that day's close / today's latest price (`prices_daily.csv`; final days are not touched), and all points = the 1T chart (`intraday.csv`). The script marks today as `intraday` before 23:00 Berlin, refuses to finalize an intraday row whose closes were not all refreshed, rebuilds `portfolio-data.js` and deletes the incoming files on success. Cost of a full update: ~5 Haiku agents × ~100k tokens, ~2 min.

More than ~5 trading days missing (`--plan` warns): fetch the closes with `year_to_date` into the legacy `data/incoming.csv` (header `isin,timestamp_utc,price`, only dates after the last final date), then run the normal update.

Build warnings: a day-to-day ratio near 2/3/4/5/10/20/50/100/200 flagged `SPLIT` means a split – confirm, divide the whole history of that ISIN before the split date, note it in `HANDOFF.md`. Already adjusted by Scalable: FR0010342592 1:200 on 2026-07-09. Moves > 30 % are flagged for review (known, real ones: Marvell 02.06., D-Wave 21.05., AT&S 15.06., Bloom 30.07.2026; also Halbleiter 3x XS3091657729 −27 % on 05.06.2026 = 3x a −9 % semiconductor day).
`--finish` / `--finish-add` run the tests (below) and rewrite the `data-status` block in `HANDOFF.md`; do not edit that block by hand.

New instrument (only on user instruction; UPDATE_PRICES.md "New instrument"): `search_securities` for the exact ISIN (ask when unclear) → row in `data/instruments.csv` → `python data/update_prices.py --plan-add ISIN[,ISIN]` → one Haiku `price-fetcher` per printed prompt (year_to_date + seven_days into `data/incoming/ytd/` and `data/incoming/`) → `--finish-add ISIN[,ISIN]` (validates, adds the columns, merges closes + 30-min points, archives the raw file, rebuilds, tests). From then on the ISIN is in every normal update and in the benchmark search. A new position additionally needs its `positions.csv` row and logo. A chart error → `search_securities` by name, pick the ordinary share / the exact ETF, and ask the user before replacing an ISIN.

## Model conventions

- Backcast: constant share counts from `positions.csv` over the whole history (no transaction history available); price return in EUR, dividends of distributing stocks not included.
- Engine fill rule: forward-fill gaps; before an instrument's first quote it counts flat at its first quote (SpaceX from 2026-06-12).
- Benchmarks are normalized to the portfolio's start value of the selected range. Benchmark cards (built in the UI, not saved): `{weights: {ISIN: %}}`, bought at the first day of the selected range (1T: at the previous close) and then held – buy and hold, no rebalancing (user, 27.09.); only a card with 100 % is drawn. `my_depot` ("Mein Depot", the only preset) is the user's real Scalable depot with fixed quantities of 25.09.2026 (update its holdings in `benchmarks.csv` only on user instruction); IE00BF01VY89 has no Scalable quotes 26.01.–09.04.2026 (flat forward-fill).
- Measurement box: the yacht box as in the app; beside it a "Mein Depot" box with "Gleicher Wert" = `equalValueWindow` (the depot's return over the span × the portfolio value at the span start) and "Echt" = `benchmarkRealPl` scaled to the "Mein Depot (€)" field.
- "Startwert" scales all EUR amounts of the selection; % metrics are scale-invariant.
- Intraday (1T): 30-min slots 07:30–23:00 Berlin (a point goes to the nearest slot, the latest wins); per session the previous daily close until the first quote, then forward-fill; an ISIN without intraday quotes is flat at its daily price; slots after the last fetched point stay empty. 1T falls back to the 2 daily points when `intraday.csv` does not end on the last daily date.
