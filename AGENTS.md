## Updating prices through the Scalable MCP (read-only!)

Use only `get_security_chart`, `get_security_quote`, `search_securities` (plus `get_portfolio_holdings` / `get_portfolio_overview` when the user asks to refresh the depot data). Never call order, savings-plan, watchlist, price-alert or other write tools. Omit `portfolioId`.

Timeframes (tested 25.–27.09.2026; one ISIN per call, no date parameter): `one_day` = 10-min points of 2 sessions; `seven_days` = 30-min points of ~6 sessions, the last point per day (~20:59 UTC) is the close; `one_month` = 2-hour points (~05:30, 07:29 … 19:29 UTC) of ~1 month, the last point of a day is NOT the close (only the newest day ends with the ~20:59 close point); `three_months` / `six_months` / `year_to_date` = one point per trading day = the daily close (~20:59 UTC; three_months checked equal to `prices_daily.csv` on 67 of 67 days); `one_year` = every 2nd trading day, `max` = monthly (month-end closes, ~10 years; single months can be missing) – never for daily rows, only for the history before 2026 in `data/prices_history.csv` (user 28.09.: `--plan-history` / `--finish-history`, and every new instrument's backfill). Ignore `closingReferencePoint`. Since `year_to_date` restarts every January, never delete old rows.

**Subagents (user rules, 27.09.):** Haiku agents **only for price lookups**, always with clear, script-checked instructions and thinking ON. Haiku has no effort setting: start them as agent type `price-fetcher` (model haiku) and begin every fetch prompt with the line `Thinking ON: think step by step before each tool call and before writing each file.` One agent per batch of ≤ 25 ISINs for updates, ≤ 10 for backfills (the hook shrinks each result to one line). **Everything else** delegated (UI, code, review) runs on **Opus 5.5 with effort high or xhigh**: the Agent tool has no effort parameter, so use agent type `dashboard-designer` (Opus, xhigh) or `opus-engineer` (Opus, high), both in `.claude/agents/`. Ask the user whenever something is even slightly unclear.

**Every update follows `UPDATE_PRICES.md`** (skill `update-quotes`; user 25.09.: fetch the intraday prices on every update; user 27.09.: always 30-min for the last seven days and 2-h for the last month):
`python data/update_prices.py --plan` (empties `data/incoming/` except `ytd/`, prints one ready agent prompt per batch) → one `price-fetcher` agent per prompt, all at once: per ISIN `get_security_chart(isin, "seven_days")` and `(isin, "one_month")`; the hook writes `data/incoming/<ISIN>.csv` and `data/incoming/2h/<ISIN>.csv` → `python data/update_prices.py --finish` (check → merge → rebuild → tests → status block in `HANDOFF.md` → report; prints a ready re-fetch prompt for missing/bad ISINs). `--check`, `--dry-run` and the plain run remain available as single steps. The last seven_days point per Berlin date = that day's close / today's latest price (`prices_daily.csv`; only new days, final days are never touched); all seven_days points go to `intraday.csv`, all one_month points to `intraday_2h.csv` (per ISIN and day the newest fetch replaces the stored points, except a shorter cut-off first session). The script marks today as `intraday` before 23:00 Berlin, refuses to finalize an intraday row whose closes were not all refreshed, rebuilds `portfolio-data.js` and deletes the incoming files on success. Cost of a full update (27.09.): 2 Haiku agents × ~55k tokens, 100 calls, ~40 s.

More than 5 weekdays since the last final close: `--plan` adds `three_months` to the prompts and the merge fills the missing closes from it (only new days that seven_days no longer covers). More than ~60 weekdays: `--plan` warns → ask the user (the older closes need `year_to_date` into the legacy `data/incoming.csv`, header `isin,timestamp_utc,price`, only dates after the last final date).

Build warnings: a day-to-day ratio near 2/3/4/5/10/20/50/100/200 flagged `SPLIT` means a split – confirm, divide the whole history of that ISIN before the split date, note it in `HANDOFF.md`. Already adjusted by Scalable: FR0010342592 1:200 on 2026-07-09. Moves > 30 % are flagged for review (known, real ones: Marvell 02.06., D-Wave 21.05., AT&S 15.06., Bloom 30.07., Nebius 30.07., IREN 30.07.2026; also Halbleiter 3x XS3091657729 −27 % on 05.06.2026 = 3x a −9 % semiconductor day and IREN −24 % on 05.02.2026; confirmed by the user).
`--finish` / `--finish-add` run the tests (below) and rewrite the `data-status` block in `HANDOFF.md`; do not edit that block by hand.

New instrument (only on user instruction; UPDATE_PRICES.md "New instrument"): `search_securities` for the exact ISIN (ask when unclear) → row in `data/instruments.csv` → `python data/update_prices.py --plan-add ISIN[,ISIN]` → one Haiku `price-fetcher` per printed prompt (year_to_date + seven_days + one_month + one_year + max; the hook writes `data/incoming/ytd/`, `data/incoming/`, `data/incoming/2h/`, `1y/`, `max/`) → `--finish-add ISIN[,ISIN]` (validates, adds the columns, merges closes + 30-min + 2-h points + the history into `prices_history.csv`, archives the raw files, rebuilds, tests). A thinly traded title whose `year_to_date` close is a later trade than the last 30-min point keeps that close. From then on the ISIN is in every normal update and in the benchmark search. A new position additionally needs its `positions.csv` row and logo. A chart error → `search_securities` by name, pick the ordinary share / the exact ETF, and ask the user before replacing an ISIN.

## Model conventions

- Backcast: constant share counts from `positions.csv` over the whole history (no transaction history available); price return in EUR, dividends of distributing stocks not included.
- Engine fill rule: forward-fill gaps; before an instrument's first quote it counts flat at its first quote (SpaceX from 2026-06-12).
- History before 2026 (user 28.09.): month-end closes back to ~2016 and every 2nd trading day 29.09.–29.12.2025 (`res` per date, `ctx.dailyFrom` = first daily index). Chart, Rendite, p.a., Max. DD and Monatsrenditen use every point; Vol., Sharpe, Sortino, VaR, best/worst day, Beta, Korrelation, Tracking Error, the correlation matrix and the risk contribution use only the daily returns (`series.dailyOff`, `stats().riskFrom`). A range that reaches before the date where ≥ 90 % of today's value of the selection has real quotes starts there (`PFEngine.coverageStart`, 31.05.2021 for all positions); the headline names the titles still held flat (`notQuoted`). YTD starts at the previous year's last price (29.12.2025); a preset target that falls between month-end rows takes the nearer date (1J → 29.09.2025). With history in the range the chart's x-axis is by calendar time (years as labels over > 800 days), and Monatsrenditen switch to one block per year (Jan–Dez + Jahr). Known real history moves: Bloom +193 % and D-Wave +198 % in Nov 2024 (flagged "SPLIT 1:3?", not splits); SanDisk +31 % on 30.07., Applied Digital +37 % on 06.02., CleanSpark −25 % on 05.02.2026.
- Benchmarks are normalized to the portfolio's start value of the selected range. Benchmark cards (built in the UI, not saved): `{weights: {ISIN: %}}`, bought at the first day of the selected range (1T: at the previous close) and then held – buy and hold, no rebalancing (user, 27.09.); only a card with 100 % is drawn. `my_depot` ("Mein Depot") is the user's real Scalable depot as a weighting preset (share counts of 25.09.2026 × prices of 28.09.2026; editable in the UI like every card, user 28.09.; change its weights in `benchmarks.csv` only on user instruction); IE00BF01VY89 has no Scalable quotes 26.01.–09.04.2026 (flat forward-fill).
- Measurement boxes (user, 29.09.): a caption with the measured span and one row of equal boxes – the Yacht ("Portfolio" / "Was-wäre-wenn") first, then one per benchmark shown in the chart ("Mein Depot" first) – each with "● name  %", start → end value of the span in € and the € change; the values are those of the drawn lines (VALUE series also in Gesamtrendite mode, typed Startwert applied). No "Gleicher Wert" any more (`equalValueWindow` stays in the engine, unused by the UI); the "Echt" row and the "Mein Depot (€)" field were removed on 28.09. with the locked card. The headline above the chart is only the legend line; period and notes are the muted line `#chartNote` under the chart.
- "Startwert" (user, 29.09.): empty = every line (Yacht and benchmarks) starts at the Yacht's value at the range start; a typed value = every line starts there and all EUR amounts of the selection scale (% metrics are scale-invariant). Buttons beside the field: "Yacht" (empties it) and "Mein Depot" (the real depot's current value, `PFEngine.depotNow`). The former "nur Benchmarks" toggle is gone.
- Top of the page (user, 29.09.): two blocks – "Yacht-Portfolio" = always the real Yacht (all positions, original shares; never Startwert, filter or what-if) with its change over the period, and "Mein Depot · Scalable" = the real depot's value (`depot.csv` shares × latest prices) and its G/V seit Kauf (Scalable's MAX return at the snapshot, carried forward with the prices). The "Statistik" panel beside the chart: Wert, Rendite, p.a., Vol. p.a., Sharpe, Max. DD (no Sortino), right of the chart as wide as the free space allows, otherwise above it.
- Chart interval (user, 27.09.; `PFEngine.chartInterval` / `gridFrame`): 1T and 1W 30 min, 1M 2 h, 3M and longer daily; a custom Von/Bis range by its length (≤ 7 calendar days 30 min, ≤ 31 days 2 h, else daily). A finer interval is used only when every session of the range was collected, otherwise it steps down (30 min → 2 h → daily; a note under the chart says so). Main chart, hover, measurement boxes and the drawdown chart follow it; Kennzahlen, Monatsrenditen, tables and sparklines stay daily. Grid rules (`build_data.py`): Berlin slots 07:30–23:00 (30 min) / 07:30…21:30 + 23:00 (2 h), a point goes to the nearest slot (the latest wins), a final day's 23:00 slot is its daily close; per session the previous daily close until the first quote, then forward-fill. A sub-daily chart starts at the daily close of the range start (1T: the previous session as grey context) and benchmark cards are bought there.
